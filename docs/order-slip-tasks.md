# Admin order-slip processing

Both Firebase callables require a Google session with a Boolean Admin claim. The inbox is shared by Admins within one environment.

## Mobile contract

- `submitOrderSlipTask({requestId, photoBase64})` accepts an app-generated stable UUID and a standard base64 JPEG. Send one full slip, up to 4 MiB decoded and 16 megapixels. Retry an uncertain submission with the same account, UUID and original bytes. The server applies orientation, removes metadata and stores a normalized private JPEG.
- `readOrderSlipTasks({action: "get", taskId, includePhoto?: boolean})` returns the task summary and `preview`, with `photoBase64` when requested. Poll with photo retrieval omitted. `readOrderSlipTasks({action: "list", cursor?: string})` returns `{tasks, nextCursor}` with newest tasks first, up to 25 per page. The returned cursor is opaque to the app.
- Summaries contain `taskId`, `status`, `failureCode`, `createdAt`, `updatedAt` and `expiresAt`. Timestamps are UTC ISO strings. Status is `QUEUED`, `PROCESSING`, `READY` or `FAILED`. Retries can move a processing task back to queued. Failure codes are `photo_unavailable`, `invalid_preview` and `processing_unavailable`. The worker commits the preview and `READY` together. Failed, pending and expired tasks have no available preview. The app can reopen a ready task without starting new inference.
- The version 1 preview has `sources` with up to 40 `{id, text}` snippets, `prefill`, and `paperAmounts`. Each proposed field has `value`, `confidence` and `sourceLineIds`. Confidence is `high`, `medium`, `low` or `unknown`. Unknown values are null. A citation points to a model-generated transcription staff can verify against the photo.
- `prefill.items` contains separate `productId` and `quantity` fields per photographed line. `prefill.pickup` contains `year`, `month`, `day`, `hour`, `minute` and `meridiem`. Hours are 12-hour and meridiem is AM or PM when known. The other prefill fields are `contactName`, `contactPhoneNumber`, `notes` and `depositReceivedCents`. `paperAmounts` contains `totalCents`, `payCents` and `balanceCents`. An unreadable slip can produce an empty, ready preview.

Resolve contacts with the usual client selector. Refresh catalog revisions and combine repeat product lines after review. Resolve the reviewed local pickup in America/Toronto and fill missing values explicitly. Use existing booking availability and selected blocks for allocation and revision fields. The order flow owns stable order and item UUIDs, current pricing and final validation. Prefill paper PAY as a pending suggestion and confirm cash was actually received before sending `depositReceivedCents`. Set `depositRequiredCents` to zero for this workflow. The task creates no client, order, allocation, payment or receipt.

## Development provisioning and release

1. Fill all `SLIPS_*` settings from [the Functions example](../functions/.env.example) in the target project's ignored dotenv file. Use a distinct runtime service account and Cloud SQL IAM database user. Grant the runtime Cloud SQL Client and Instance User, database CONNECT and public schema USAGE. Set the bucket to `<project>-order-slips` in the Functions region. Use uniform access and enforced public access prevention, with no versioning, soft delete, retention lock or direct mobile access. Set a single Delete lifecycle rule at age 30 days. Grant only object create, get and delete to the runtime on this bucket.
2. Enable Cloud Tasks and Cloud Scheduler. Firebase provisions the regional `processOrderSlipTask` queue and restricts invocation and queue enqueue to the Slips runtime identity. Give the runtime permission to act as itself for the OIDC task target and retain the Cloud Tasks service agent's standard permissions. The scheduler runs reconciliation once per minute. The release operator needs read access to the queue, worker IAM and bucket configuration, in addition to the normal release grants.
3. For Vertex, enable the AI Platform API and grant only `aiplatform.endpoints.predict` to the runtime. Provision and verify access to Gemini 3.8 Flash with Montréal Provisioned Throughput. For OpenAI, enable Secret Manager and provision a project API key in the named secret. Grant the runtime Secret Accessor on that secret alone. Select `openai` explicitly. OpenAI requests send the full slip with `store: false`. Verify the selected provider's processing location, logging and retention before sending real customer images. Provider and model are pinned on the task. Drain pending tasks before changing configuration or removing old credentials. [Vertex data controls](https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/zero-data-retention), [OpenAI data controls](https://developers.openai.com/api/docs/guides/your-data)
4. Review the target schema diff through [the managed release procedure](releases.md). The new maintenance adds only the task table and indexes before registering the compatible schema. It uses the existing guarded schema procedure to preserve order protections and pauses writes while private native checks are temporarily removed and restored. Connector roles get temporary REFERENCES only for registration, then all task privileges are revoked. The follow-up transaction adds the task-state constraint. Verify scoped table grants and catalog column reads before deploying the Functions codebase.

The queue receives task ID and dispatch generation only. Processing is leased and retries are bounded. Expired tasks disappear from reads after 30 days, then the reconciler deletes the stored photo generation before deleting its row. The bucket lifecycle also removes orphaned uploads. SQL backups and provider retention follow their respective environment settings.

After a separately authorized Development release, submit a synthetic complete slip and an ambiguous slip. Verify both can be reopened by a different Admin and Staff-only requests are denied. Observe the saved status and preview, fetch the private photo, and confirm product revisions, capacity and cash confirmation are still resolved in the order editor. Verify the effective privileges, queue, scheduler, bucket, and selected model. Exercise expiry with a disposable fixture. Automated tests use stubbed providers and storage and never call cloud services.
